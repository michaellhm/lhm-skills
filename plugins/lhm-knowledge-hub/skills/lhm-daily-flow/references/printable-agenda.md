# Printable daily agenda

Michael confirmed this format on 20 November 2026 after using the Wednesday and Friday agendas. This reference stores the reusable layout only. Never copy a private agenda, client backlog, family booking, mailbox identifier or dated task list into the plugin.

## Content and order

- **Header:** weekday and full local date; one short sentence describing the day's focus.
- **1 Morning quick wins:** exactly three verified, small next actions for Michael, usually about 5–15 minutes each. Prefer existing ready drafts, short reviews and specific unblocks. Reconcile sends, completions and owners first; never invent or reopen work to fill three slots. If fewer genuine quick wins exist, show those and explain the gap. Draft review/send remains subject to existing sending authority.
- **2 Onboarding, handovers and meeting wraps:** concise outcomes and next owners, not repeated summaries. A sent wrap can still have an unfinished action handoff; a prototype send does not prove client approval.
- **3 Website focus:** the selected website reviews/build decisions and the main substantial deliverable. The heading can become Website & analysis focus when needed. Show which work comes first and which needs the next available block.
- **4 Client follow-ups:** the concrete reply, decision or deliverable owed. Keep different outcomes for the same client separate, such as website feedback versus promised spend/referral analysis.
- **Sidebar — Meetings / local timezone:** verified bookings and material clashes. Estimate useful gaps conservatively, allowing for travel, breaks and preparation; do not silently move bookings.
- **5 Systems & admin:** short, bounded investigations and cleanup, after delivery priorities unless genuinely urgent.
- **Other carryovers:** only material retained promises or unfinished work. Mark these as carryovers, not fresh daily commitments. An optional Already moved note can stop stale completed items resurfacing.

Respect later user changes to categories, order and priorities. Keep the private checkpoint's evidence links and coverage gaps authoritative; the PDF is a readable attention index, not a second task board. Omit unverified leads from the actionable checklist or clearly place the missing verification in carryovers. Do not put the entire historic Inbox on one page.

## Visual specification

Use a clean portrait A4 page (approximately 595 × 842 points), white background and approximately 32-point margins. Match an available user-approved prior PDF visually when requested. Keep the main column around 64% and a softly shaded sidebar around 34%, separated by a clear gutter.

- Dark navy text, restrained teal section labels, thin pale divider rules and a very light grey-green sidebar; no heavy decoration.
- Left-aligned, readable sans-serif typography: roughly 20–21-point title, 10-point section headings, 9–10-point action titles and 8-point supporting lines. Draw empty square checkboxes rather than relying on an unsupported checkbox glyph.
- Each action has a short title and, only where useful, one concise line for status, dependency or next step. Keep wrapping clear of checkboxes and inside its column.
- Use a short footer such as: Planning checklist — work menu, not new bookings or a promise to finish everything today.
- Shorten wording and reduce optional carryovers to fit; keep full detail in the checkpoint rather than shrinking text below readable sizes. Do not silently remove an agreed priority or create a second page while claiming one-page output.

## Save, verify and present

1. Read the current private checkpoint and reuse its verified dispositions. Refresh only materially stale evidence required for the agenda; formatting is not authority for another broad sweep.
2. Use available document/PDF libraries. In Codex desktop, discover the bundled runtime through `load_workspace_dependencies` before assuming the system Python has ReportLab or other packages. Use available equivalents on other surfaces; do not hard-code a developer's runtime path into the workflow.
3. Save `YYYY-MM-DD — <Weekday> Priorities.pdf` beside the verified participant's daily checkpoint. Preserve an established alternative filename if updating an existing agenda. Keep personal planning out of shared Drive/client work folders and Git; no shared fallback if private storage is unavailable.
4. Verify the file is readable, exactly one portrait A4 page, with all agreed priorities, the correct local date/timezone and exactly three quick wins unless fewer are genuinely available. Render it and visually inspect for clipping, crowded wrapping, unreadable text and checkbox alignment. Text extraction alone is not visual QA.
5. Link the PDF and actual validation result in the same checkpoint, then read back the change. Open the PDF with the available editor/preview tool and return its link. A queued open request is not proof the user has viewed it.
6. Creating/opening a PDF does not authorise a print job, email, upload, task mutation, calendar booking or schedule. If generation, visual inspection or save/readback fails, state which check is incomplete; never call it print-ready or saved without evidence.

## Manual acceptance checks

- An agenda request after a completed sweep produces a PDF, not only chat/Markdown, without repeating the sweep unnecessarily.
- Three genuine quick wins appear first; a completed send is not reused as an unsent quick win, and fewer than three are not padded with invented tasks.
- A meeting-heavy day retains its fixed bookings and marks substantial work as the next available block instead of promising it all today.
- Another participant uses their own scope, private destination and preferences; Michael's family bookings and private records never enter their agenda.
- Overflow is solved by concise wording/optional carryover reduction with the full checkpoint preserved, followed by page-count and rendered visual checks.
- An unavailable PDF runtime or denied private write returns an explicit gap and unsaved conversational agenda, without shared storage fallback or a success claim.
