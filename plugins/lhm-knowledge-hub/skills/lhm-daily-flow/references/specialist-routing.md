# Specialist routing for daily execution

Resolve the requested outcome first, then verify the installed agent, skill and tools in the chosen executor. Source files are a catalogue, not proof that ChatGPT, Claude, Codex or a team member can invoke them. Read the selected agent/skill and its current contracts; preserve existing task owners and approval boundaries. An agent leads the work; skills perform bounded specialist functions. Naming an agent in a prompt does not spawn or delegate work.

## Common task routes

| Outcome | Owning lead | Specialist skills / handoff |
|---|---|---|
| Ads goals, duplicate conversions, GA4 imports | `lhm-marketing-hub:google-ads` | `google-ads-conversion-audit`; approved settings changes through `google-ads-implementation`, acceptance through `google-ads-delivery-qa` |
| Website/GTM/GA4 event firing | Website owner for the actual platform, with Google Ads Lead for bidding definitions | `lhm-marketing-hub:analytics-tracking`; `lhm-wordpress-hub:astro-lead` or `wordpress-lead` for supported site changes. A conversion audit is not itself a website repair skill. |
| Astro site readiness, quiz links and deployment | `lhm-wordpress-hub:astro-lead` | `astro-build`, `website-delivery-qa`; analytics-tracking for measurement. Verify quiz/GHL capability separately; do not invent a dedicated quiz skill or assume access. |
| Full site or landing-page work of unknown scope | `lhm-wordpress-hub:website-orchestrator` | Route to the existing build, prototype, landing-page or content-only lane |
| Organic search diagnosis and planning | `lhm-marketing-hub:seo` | Owning audit/research/brief skill; `seo-delivery-qa` |
| Final customer-facing words | `lhm-marketing-hub:content` | Relevant writing skill and content acceptance; channel specialist supplies evidence/brief |
| GBP/local search cycle | `lhm-gmb-hub:gmb-orchestrator` | Existing phase agent and its bounded skills |
| Content batch production | `lhm-content-engine:content-orchestrator` | Existing outline/write/quality/publish chain |
| Task ownership, blockers and team handoffs | `lhm-project-hub:pm-orchestrator` | `basicops-task-manager`, `team-work-brief` or relevant project skill |
| Email | `lhm-inbox-hub:inbox` | Relevant inbox skill; honour actual send authority |
| Finance | `lhm-finance-hub:finance-orchestrator` | Owning finance skill; preserve private data boundary |
| Knowledge and learning | `lhm-knowledge-hub:knowledge-orchestrator` | Relevant vault/flow skill; close through `lhm-learn:learn` |
| Skill source improvement/release | `lhm-system-ops:lhm-skill-maintainer` (skill) | Governed source workflow; publication agent only for its authorised release scope |

Only use verified command names. For example, `/lhm-marketing-hub:start-googleads` exists in source and loads the Google Ads agent. An agent identifier is not automatically a slash command. In another executor, ask it to load the named agent/skill if available; otherwise supply the bounded procedure and identify the access gap.

## Coverage and Learn

Before each prompt, record lead, skill chain, capability availability and coverage as full, partial or gap. Reuse prior discovery and provide the existing client/task context so team members do not repeat the founder interview. Keep final acceptance and next owner explicit.

If coverage is partial, execute supported steps and bound the uncovered portion with evidence and checks. At session finish, Learn captures the successful reusable procedure, failures, corrections, approvals and test results. Update an existing owning skill before proposing a new one. A single unverified diagnosis is not a proven repair method, and ordinary Learn does not authorise automatic creation, publication, merge or installation. If Learn is absent, return this evidence for the coordinator; do not pretend the command ran. Deduplicate worker and daily-close learnings by source/outcome.
