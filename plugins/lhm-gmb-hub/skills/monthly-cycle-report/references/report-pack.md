# Report pack

## Overview

Use the following layout as a guide. Aim for a readable one-page summary with details in the evidence file. Include all registered locations even if a row is unknown.

1. **Title and dates:** client, reporting period, work-planning date, draft/final status.
2. **Highlights:** short bullets establishing the main job, key result, urgent issue and useful opportunity where supported. Avoid a formulaic fixed number if fewer facts matter.
3. **Goal:** one sentence tied to the canonical goal record.
4. **Location table:** location, recorded programme stage, performance/delivery status with short reason, this month's role. A single-location report can use a short status block.
5. **One ordered checklist:** scope label, action and done condition. Full owner/dependency/evidence details belong in the linked action briefs. Separate immediate work from the next-work queue. Close Month 0 when needed instead of showing phase status without a completion plan.
6. **Coach link and next review:** verified evidence/prompt links and what will be measured next. Note important measurement limitations in plain English.

## Evidence and action briefs

Include source ledger, agreed/provisional goals, per-location phase evidence, current/prior metrics and calculations, actual focus-keyword coverage, previous-change outcomes, diagnosis with confidence and competing explanations, and specific unanswered questions with owners. Add the other phase-specific sections required by the diagnosis reference. Use gaps explicitly; do not manufacture seven current rankings if only three are available.

For each proposed action include:

| Field | Required content |
|---|---|
| Goal and scope | Goal ID/outcome; all locations or named clinic(s) |
| Finding | Measured fact and dated source; hypotheses labelled |
| Action | Exact change or bounded remaining check; existing URL/profile where known |
| Owner | Verified owner or clearly proposed handoff |
| Dependency | Required input, decision, access or prior action |
| Done | Observable completion evidence; pending stays open |
| Review | Metric, consistent scope and next review window |

Keep shared work once, with the locations it serves. Do not repeat a complete site architecture brief for every profile. If consolidating old reports, remove conflicting priority instructions from the current pack, retaining historical context only as labelled evidence. The overview and coach must agree on the current task order.

## Copyable AI coaching prompt

Populate this with the verified report URLs, goal, scope and actual stage table; no unresolved placeholders in a delivered prompt.

> You are my SEO work coach. Use plain English and guide me through the client's current checklist one task at a time.
>
> Read the overview and evidence report at the supplied links. If you cannot access them, ask me to attach the files. Do not pretend to have read them. Use the stated business goal, reporting period, current meeting decisions and each location's recorded stage.
>
> Start with a brief explanation of the priority, then the first unblocked task. Check available project records, meetings, GA4, Search Console, Ads and profile evidence before asking me factual questions. Do not repeat analysis already supported in the report unless new evidence or staleness warrants it. Explain technical terms as they arise.
>
> For the current task, show the outcome, location scope, exact page/field or proposed wording, short steps and completion check. Ask one necessary question at a time. When another owner must answer, draft a specific question, name the owner and dependency, and continue independent work.
>
> Keep shared work once and local checks separate. Do not reset completed audits, infer phase completion from time passed, or turn missing data into a green status. Use only supported services and current client decisions. Separate booking events from unique patients and website positions from Maps rankings.
>
> Follow the user's existing execution authority. A report is not permission to publish site/profile changes, send messages, assign tasks or incur costs. Verify any authorised work before marking it complete. Record goal, scope, URL, date, evidence, status, remaining owner and next step. Never save patient details.
>
> At handoff, prepare the canonical project/Obsidian update and link verified Drive deliverables. Finish with the next action and the metric/date for checking results.

Include the client's current ordered task IDs or refer to the verified overview as the single authoritative queue, so edits cannot leave competing embedded lists. The coach should help the team act and learn, not overwhelm them with the entire evidence report again.

## Board reconciliation

Include a short Already on the board block in the overview. Link existing meeting and SEO tasks; do not repeat their full briefs. Evidence must distinguish reported completion from independently verified outcomes and retain unresolved dependencies. The coach starts by reconciling these linked tasks before opening new work.
