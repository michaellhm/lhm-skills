# Website host contract

`site_workspace.py` is installed root-owned beside the task router. The App key and configuration live under `/etc/lhm-sites`, mode0700 directory,0600 files. Only the supervisor can mint installation tokens. Git commands run as the selected worker; tokens are passed only in ephemeral Git configuration environment, never remote URLs, command arguments, files or output. Repository permissions are Contents read/write plus Metadata read; installations and tokens are restricted to registered repositories. No org/admin/workflow permissions.

Registration contains `github_app: {client_id, installation_id, private_key}`, `commit_name`, `commit_email`, and `sites` keyed by site ID. Each site records `client_id`, `repository` as owner/name, `default_branch: main`, `mode: build|live`, `deployment_verified: true`, `authority_source`, optional `scope_note` quoting the latest verified human clarification, `preview_url` and `checks` as command-argument arrays. Values are verified runtime configuration, never credentials committed to source. The registry must reject two site IDs for the same repository; locks also use a case-insensitive repository hash.

The dispatcher creates ordinary task context then starts `lhm-site-<request-id>` as a host supervisor. That process owns the repository lock for the provider's entire lifetime. The worker receives root-owned `site-location.json`, actual checkout cwd, original task context and shell/build tools only for this registered website route. Credentials/other sites remain outside its mounts. The existing per-provider lock remains for old task context; it does not replace the repository lock.

Pilot migration: snapshot the exact task directory and hash every draft; save the original receipt/session UUID. Verify the worker is idle before stopping it, stop only its systemd unit, archive the old terminal socket, and create root-owned `site-resume.json` containing the original thread_id. Start the site supervisor on the original request ID. It re-verifies that request, preserves task context/drafts and starts the same provider conversation against the real checkout. Verify actual session link, working directory and original draft hash. If resuming is unsupported, preserve the original and report the exact gap; don't silently start another task.

Checks must be run as the worker, never root, with a clean environment and bounded runtime. Save logs in the host site evidence directory. `checks.json` must be host-owned and record exact `commit`, `passed`, command results/log paths and task ID; publication refuses stale/missing checks. Recheck HEAD and dirty status after checks. Never run repository-controlled hooks, package scripts, credential helpers or filters as root. Do not allow `.github/workflows` changes through this App's current permission scope.

On a new site, verify repository/deployment metadata and add a scoped registration through the authorised host setup route. An App installation expansion needs the user's approval; don't grant all-repository access by default. The skill and host tools are reusable, but registrations are client-specific.

Rollback: preserve unpublished work and stop only the pilot worker/supervisor after inspecting state. Restore the source files from the recorded deployment backup and remove the pilot site registration to return future admissions to the existing task route. Keep the new checkout, prior task archive and saved conversations. Revoke the App installation/key only under applicable authority, never as incidental cleanup.
