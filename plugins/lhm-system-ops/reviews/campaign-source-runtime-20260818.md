No third-party integration was added.

## Pass 2 — Platform Engineer
Imported the fab28d92 executable runtime and both outage fixes (quoted systemd path and untracked-file enumeration). Added one branch-owned adapter executable installed under every absolute profile command, strict backend config validation, exact source/destination registration checks, manifest-scoped authentication/capability preflight, publisher idempotency key and full-content read-back. The installer creates or validates `sourceworker`, ownership, registration/config directories, executable links and the hardened systemd sandbox; it never enables the path.

## Pass 3 — QA Tester
The clean-release revision adds a regression fixture proving both plugin validation and release construction identify generated Python bytecode, and verifies the plugin tree is clean. The isolated end-to-end test launches the four actual adapter binaries as subprocesses against fake connector processes, traversing Drive and Fathom reads, packaged production, idempotent publication and full-content read-back. Runtime tests also cover source failure, one incident/no delivery, restoration duplicate no-op, arbitrary-ID rejection, least privilege and both outage regressions. Live authenticated smoke tests remain post-deployment; none were attempted in this branch workspace.

## Pass 4 — Security/Reliability Reviewer
Hermes retains queue/status access only. Adapter configuration accepts argv arrays with verified absolute executables, not tokens or shell strings. Backends retain their existing credentials outside Hermes/repo/logs. Exact registration, closed fields, account/executable/config checks, authenticated source/folder probes, content hashes, durable atomic JSON, deterministic publication idempotency and exact read-back fail closed. The oneshot adds private devices, kernel/control-group protection, SUID/SGID restriction, locked personality and a restrictive umask. Generated `__pycache__` directories and `.pyc` files are ignored and rejected by validation and release construction rather than silently packaged.

## Pass 5 — Plugin Release Manager
Prepared clean version 0.4.0 assets only. Exact release/install/smoke/rollback steps are in `references/source-production-release.md`; rollback stops and disables only the source-production path, preserves run evidence, restores the previously recorded archive/config/units (or removes only the five installed adapter/runtime paths and two units when no prior version exists), reloads and verifies systemd, and requires separate approval before re-enabling a prior version. Remaining human actions are: Michael reviews and merges; approves a release from the immutable commit; an operator records the verified absolute native backend argv mapping without secrets; Michael separately approves installation; an operator installs the exact root-owned registration for the Drive file, Fathom recording and Drive destination; runs manifest-scoped preflight and the read-only authenticated smoke; Michael reviews that evidence and separately approves path enablement. Publication is not installation or deployment authority.
