# Codex execution bridge release contract

This additive bridge supersedes any inactive generic `lhm-codex-dispatch.path` contract. The CTO plugin dispatcher remains separate. Hermes may submit and read receipts through `lhm-codex-dispatch`; it never receives the worker credential or inference environment.

Install only from an approved immutable plugin release: install the container client at `/opt/data/profiles/lhm_brain/bin/lhm-codex-dispatch`, the host worker and queue handoff at `/usr/local/libexec/lhm-codex-execution-worker` and `/usr/local/libexec/lhm-codex-queue-handoff`, and both units root-owned. Create `incoming` as `root:hermes` mode `0770`, `receipts` and `incidents` as `codexworker:hermes` mode `0750`, and `processing`, `failed`, and `worker-runs` as `codexworker:codexworker` mode `0700`. At every worker launch the root-owned service preflight restores only `mask::--x,user:codexworker:--x` on `/home/hermes/.hermes`, `/home/hermes/.hermes/profiles/lhm_brain`, and the queue root. The root-owned queue-local handoff then restores `default:mask::r--,default:user:codexworker:r--` on `incoming` before granting `mask::r--,user:codexworker:r--` only to direct regular non-symlink `*.json` entries already present. This ordering covers the triggering file and lets later tempfiles retain effective named-user read access across the submitter's chmod `0640` and atomic rename. `-n` prevents implicit mask recalculation; no recursive, group-membership, world-read, unrelated named-user, profile, or vault grant is allowed. Enable `lhm-codex-execution.path`. Explicitly disable the obsolete `lhm-codex-dispatch.path` if present. Do not stop the Telegram gateway.

Before enabling, run `runuser -u codexworker -- env -i HOME=/home/codexworker CODEX_HOME=/home/codexworker/.codex PATH=/home/codexworker/.local/bin:/usr/bin:/bin /home/codexworker/.local/bin/codex login status` and retain only whether it reports ChatGPT login. Never retain credential output. Codex CLI 0.147.0 requires writable app-server state even for `exec --ephemeral`; the worker therefore creates a mode `0700` runtime home inside the request's already-confined `worker-runs` directory and exposes only the existing read-only `auth.json` through a symlink. The systemd unit must keep the real `/home/codexworker/.codex` out of `ReadWritePaths`. Failed subprocess evidence is limited to exit status and the final 4000 redacted characters of each captured stream.

Smoke-test generic, marketing, knowledge, auth-failure, invalid-profile, duplicate, timeout and existing Claude/repository routes. Record an OpenRouter metering snapshot immediately before and after the entire controlled suite and require byte-identical evidence. Every positive request must produce a valid receipt selecting `codex`, `openai-codex`, subscription-backed authentication and review-only authority. On any missing, malformed or failed positive receipt, stop, disable the candidate watcher and execute the rollback below before investigating. Zero new OpenRouter generations and no hermes-2 worker inference are required live evidence.

Rollback: disable `lhm-codex-execution.path`, wait for the oneshot worker to exit, restore the recorded prior unit/file inventory (including the prior service bytes and queue-handoff executable), restore the four recorded pre-install ACL states byte-for-byte with `setfacl --restore` for `/home/hermes/.hermes`, `/home/hermes/.hermes/profiles/lhm_brain`, the queue root, and `incoming` (including its access and default ACLs), remove only replacement assets that were previously absent, daemon-reload, and re-enable the prior healthy watchers. Keep receipts/incidents for audit. Request-file ACL entries leave the queue when those files are processed; rollback must not delete retained receipts or incident request evidence. This does not authorise Hermes or OpenRouter to perform substantive work while Codex is unavailable.
