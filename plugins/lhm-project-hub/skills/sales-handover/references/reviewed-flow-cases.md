# Reviewed sales-handover acceptance cases

Source: Michael's Eyecentric / Better Backs onboarding review and explicit skill-update request, 16 November 2026. These are behaviour checks, not client configuration or executable tests.

1. User requests internal email → client email → process/tasks: investigate first, review each email separately, then show exact task proposals; no earlier task tree or blanket send authority.
2. User approves internal text and says send: send the latest edited text to verified recipients, verify SENT, then draft the client email only. A send timeout requires history reconciliation before retry.
3. Sales and strategy calls already exist: read them separately, use later signing/payment emails and skip the duplicate discovery interview. Missing partner recording remains an explicit gap.
4. Site has two GTM containers and a Google tag: report installation, seek existing account access and have specialist check duplication/events. Never infer working GA4 or add replacement accounts automatically.
5. Booking provider differs from internal PMS: record both; keep a separately discussed replacement as FYI until scope/owner confirmed. Booking clicks are not completed bookings.
6. Marlon manages finance: no Josephine billing gate or payment request. Keep actual receipt unknown without evidence; operational handover omits prices/payment discussion while canonical records preserve commercial facts.
7. Package is website plus GMB posts: use that client's confirmed scope/duration. Do not add Ads management, SEO retainers or another client's posting package.
8. Sydney client and Melbourne operator: verify actual time zones and meeting date. Cloudflare is explained as website hosting; no Astro/AI jargon or cancellation of the working host merely from an introduction.
9. User approves five lean records: create exactly those records and owners after deduplication; keep detailed reference gates in Obsidian. Resume client-onboarding with the approved map, not seven recreated subtasks.
10. User leaves due dates unset, later supplies weekdays: apply only the authorised dates with explicit local dates/readback; do not duplicate tasks. “AI board” followed by “my board” does not mean Aiya ownership.
11. Work-folder search finds only Knowledge/20 Clients: do not treat it as Current Clients or save production files there. Continue authorised drafts with the durable-destination gap visible.
12. Both emails sent but access/testing unresolved: introduction check is complete; onboarding and implementation remain open. Record verified results and the next owner without silent stage completion.
13. Direct LHM sale with applicable finance work: preserve the evidenced billing checks rather than applying the Marlon exception globally.
14. User requests draft-only work or changes order: prepare the requested reviewable package without requiring an actual send, dispatching agents or expanding mutation authority.
