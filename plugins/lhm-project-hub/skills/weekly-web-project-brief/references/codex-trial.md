# Bounded Codex desktop runtime

Use only after Michael explicitly authorises a Codex scheduling trial. This adapter replaces the scheduler and research/controller roles, while retaining the existing source, editorial, independent review, fixed sender, weekly receipt and archive contracts. It does not install or upgrade Hermes plugins.

## Thin schedule and durable trial state

The Codex heartbeat prompt names this skill, this reference and the local trial-state directory. Keep reporting rules here and in the skill, not in a long cron prompt. Read `trial.json` in that directory before every attempt. It records the authorised Monday dates, explicit catch-up permission, automation ID, local knowledge root, remote sender host/state, source skill release and handover receipt. Never infer future send authority from an expired trial. Outside the allowed dates, pause the heartbeat without running research. After the final authorised attempt, pause it; preserve failure/uncertain outcomes for Michael. Do not automatically resume Hermes at trial end.

Prepare from Monday 07:00 Australia/Melbourne and release no earlier than 08:00. A missed wake may catch up later that same Monday only when trial.json explicitly permits that date. Do not backdate facts or send on another day. Notify only for delivery, failure or necessary human input; keep unchanged/non-actionable checks quiet.

Before first activation, verify and record that the old weekly worker is stopped and its queue watcher is disabled for the trial. Record the previous enabled/active states and the exact weekly cron ID. Pause that job where its authenticated management route is available; otherwise disable the workflow-specific queue watcher and make the queued weeks explicit in the handover record. Stop the workflow-specific watchdog timer during the trial so it cannot send competing missed-start notices. Do not alter other Hermes jobs, services or global models. Retain old queues, failed attempts and all delivery receipts. At each run, verify no old worker is active; fail closed on concurrent execution or unknown handover state.

## Research and independent review

Codex desktop reads the configured shared LHM Knowledge vault, Gmail bodies, BasicOps boards/tasks/discussions/replies and relevant Fathom transcript passages through its live authenticated connectors. Follow every required skill reference. Record access.worker=`codex-desktop`, the exact source skill path/hash, real successful reads and their times. Never claim that a CLI ran or Fathom was read when it did not. Use meetings not_required only with an evidenced reason that no unresolved decision needs a transcript.

Retain raw tool responses, coverage/pagination and evidence hashes in private local run staging outside Git. Read the previous delivered brief and all later corrections. A recovery may copy the same-week failed run into a new attempt directory, preserving originals, source timestamps and review findings. Refresh affected and newly relevant reads; do not call old source events current merely because they were copied. Complete all original review repairs and retain every dated baseline commitment or its evidenced disposition. Inactivity dates must come from each project's actual substantive BasicOps event; never apply one date to the whole portfolio.

Render using scripts/brief.py. Run quality.validate(output, require_review=False), then delegate an independent evidence-and-payload review to a fresh subagent. The reviewer must inspect retained primary evidence, prior failures, source coverage, selected-action mapping and baseline dispositions, not just the prose or schema. Only that reviewer may write accepted quality-review.json, bound to the five exact files. Allow at most two corrections per new attempt, each followed by a fresh independent review. Never self-author acceptance or weaken source gates. A concrete disclosed project gap may be accepted under freshness.md; contradictory facts and missing core reads may not.

## Existing fixed sender, shared receipt and archive

Keep Mailgun authentication in its existing Hermes environment. The desktop never reads/copies credentials. Reuse the production state directory and `receipts/<Monday>-brief.json` from runtime.md as the sole delivery authority. Local trial receipts are mirrors, never a second deduplication namespace. Before send inspect that authoritative receipt: delivered means no send; queued/sending/uncertain means reconcile provider events only; permanent failure needs human handling. Never delete a receipt or use another delivery route.

After independent acceptance, copy the reviewed run to a new `runs/<Monday>-codex-trial-<attempt>/` under the existing remote state directory. Include a byte-identical skill copy and use a run-relative skill path/hash so the evidence binding survives transfer. Preserve every original source payload and original provenance. If relocating an absolute source/baseline path, change only the path, retain the same bytes/hash, and obtain fresh independent review after relocation. Upload the entire bound evidence pack, not just email.json. Re-run the same quality.py on remote bytes before send; confirm the local and remote email hashes match. Give the sender process the modified quality.py and brief.py from the reviewed source release as temporary staged runtime files, rather than changing installed plugin links.

The registered host uses Docker container `hermes`, user `hermes`, Python `/opt/data/.venv/bin/python`; the host state `/home/hermes/.hermes/profiles/lhm_brain/workspace/weekly-web-project-brief` maps to `/opt/data/profiles/lhm_brain/workspace/weekly-web-project-brief`. Run the staged `brief.py send --week <Monday> --file <run>/email.json` inside that container with LHM_WEB_BRIEF_STATE pointing to that same production state, followed by verify. These fixed commands retain the established sender, To support only, Reply-To Michael, no CC/BCC, Monday-after-08:00 gate, atomic weekly receipt and provider-event verification. Do not send through Gmail or a generic Mailgun connector as a workaround. Poll pending delivery at most four times, 15 seconds apart, then record its actual state without resending.

After verified delivery, archive the exact reviewed brief through weekly_archive.py's snapshot contract. For desktop archive, first re-run quality.validate on the exact delivered run, require brief.week == email.week == delivered_receipt.week, and require delivered_receipt.content_sha256 == SHA256(json.dumps(email, sort_keys=True).encode()). A same-week receipt alone is insufficient; an unmatched hash blocks archive without resending. Then use snapshot(brief, delivered_receipt) to generate the note at `60 Knowledge/YYYY-Www — Web Projects.md` in the verified shared vault. If a note exists, accept only an identical checksum-bound snapshot prefix and preserve appended feedback; otherwise stop archive for reconciliation. Save and read back the note and archive receipt. Archive retry never resends email. No client record/task mutations or client messages are authorised by report generation.

## Failure and handback

Save each attempt, original review findings, controller outcome, remote delivery receipt and archive result in the local trial-state directory. On failure report what specifically needs correction. An existing same-week Hermes failure notice already satisfies the email alert: do not send another. Codex reports failures in the trial chat, including inability to access the sender or absence of the schedule wake itself. Desktop scheduling depends on the host app's scheduling availability; do not claim an unattended end-to-end test from a manual run. Trial completion means the final run outcome is recorded and the heartbeat is paused; Hermes remains paused pending Michael's decision.
