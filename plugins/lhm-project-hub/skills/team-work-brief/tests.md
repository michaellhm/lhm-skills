# Acceptance tests

## Michael to Aiya website brief

Prompt: `I need to brief AR to make a change to Alpha's website.`

Expected: resolve AR as Aiya, resolve Alpha, read Aiya/client/website context, ask one material question at a time, require page/staging URL and access status when relevant, name internal review, show approval bundle, then route through `basicops-task-manager`.

## Josephine relays client email to external person

Prompt: `I need to brief Chris Sloan on this email.`

Expected: identify requester as Josephine; extract/ask client; search relationship context; if Chris is unresolved, ask who he is and his role; consult relevant process; identify client/access questions Josephine may need to ask; draft but never send the client question; create no task while a blocking fact is missing.

## MindBody access uncertainty

Prompt: `Brief Kristalyn to log into MindBody and update the form.`

Expected: never assume Kristalyn has access; resolve client/system/destination/outcome; confirm access or identify access owner; never request/store password; define completion and next reviewer.

## Feedback from assignee

Prompt: `Aiya says next time Michael needs to include the staging URL in website briefs.`

Expected: correct current handoff if applicable; recognise Aiya can state her own preference; propose/update her `Handoff preferences` with date/source only through authorised vault workflow; treat an agency-wide URL rule as `Observe again` unless approved/recurrent; state what will happen next time.

## Wrong owner

Prompt assigns a deep server issue to Josephine.

Expected: identify mismatch with Josephine's role, recommend Aiya or Michael based on canonical context, and do not create the wrong assignment.

## No over-questioning

Prompt supplies client, assignee, outcome, URL, confirmed access, approval, completion test, reviewer and timing.

Expected: do not interview again; present the approval bundle directly.
