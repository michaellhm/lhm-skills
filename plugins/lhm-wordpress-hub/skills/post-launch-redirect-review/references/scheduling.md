Refresh documentation when installing; UI labels and runtime capabilities can change. Claude Code `/loop` is session-scoped, not the durable operating schedule. Desktop local scheduled tasks persist as configuration but execute only while the computer is awake and the app is running; runs can be missed or caught up later. Cloud schedules need separately verified repository, tools and authorised data access; don't assume local connectors/vaults carry over.

## Jaimee setup checklist

1. Confirm the approved skill release is installed in Jaimee's Claude Code environment; record version/commit. A merge to main does not itself install a plugin. Release administration is handled separately; Jaimee does not need to review the source pull request.
2. Bind one actually launched site's production hostname, verified launch timestamp, GSC/GA4 properties, website repository/main branch, existing deploy route, working/knowledge folders and Jaimee review chat. Record Michael's approval for confident exact redirect fixes and Jaimee-approved exceptions, including redirect-only commits/main release and scoped rollback. Preserve branch protections and normal permissions.
3. **24 hours after launch**, run one manual check using `confident-auto`. Use available post-launch data even if GSC/GA4 are delayed; record missing/partial coverage. Demonstrate a healthy control and any genuine404. Automatically release qualifying matches; show ambiguous ones in chat for Jaimee's approval. Do not invent an error or manufacture an irrelevant redirect just to complete the pilot.
4. After the pilot, set up daily checks for two weeks from the pilot in the site's verified timezone. Confirm a convenient daily time with Jaimee, record the exact start/end dates and ensure no duplicate monitor. One run per site at a time; recover interrupted runs before continuing. The authorisation expires at the recorded end; the runtime prompt stops writes after expiry even if the scheduler still fires. Review with Jaimee before continuing weekly.
5. In Claude Desktop's Code tab use Scheduled (or its displayed equivalent), create a local scheduled task, select the verified client working folder and daily trigger. Paste the prompt below with verified bindings. Keep normal scoped permissions, not bypass mode or blanket grants. Verify access and required checks rather than disabling protections. If scheduling tools are unavailable, use the supported UI; never edit private scheduler state.
6. Run now to test the saved task, inspect the session and live verification receipt, and verify the next scheduled run. Set an end date if supported; otherwise the prompt's expiry gate is mandatory and Jaimee disables the task at the two-week review. Desktop local execution needs the app running/computer awake; report actual catch-up times, missed coverage and permission stalls without claiming on-time execution.
